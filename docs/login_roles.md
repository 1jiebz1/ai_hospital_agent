# 登录与主任/医生角色

本次在原医管系统基础上完成登录与权限分离，业务数据仍使用仓库模拟数据。

| 角色 | 登录后首页 | 页面与数据范围 |
|---|---|---|
| 科室主任 | 运营总览 | 本科室运营、绩效、趋势、医保观察、问答和简报；公共知识库 |
| 医生 | 我的工作台 | 本人接诊、手术数量与趋势；个人工作量问答；公共知识库 |

## 使用

在 Python 3.11+ 环境下：

```bash
pip install -r requirements.txt
python scripts/manage_users.py demo
streamlit run app.py
```

首次执行 `demo` 会创建内科主任和一位医生的账号，账号分别为 `director`、`doctor`，密码随机生成并打印在终端。已有账号时不会覆盖。完整账号创建、重置密码与停用操作见 README。

登录页不允许用户自行选择主任身份，不开放公众注册。登录后侧边栏显示姓名、角色、科室与数据范围，支持退出。密码忘记后由管理员重置，重置会撤销旧会话。

## 改动

- `src/auth.py`：账号、密码哈希、登录限流、会话到期、角色与页面授权。
- `src/auth_ui.py`：网页登录入口，退出与账号切换时清空旧结果。
- `src/access.py`：按账号裁剪的只读内存数据快照，缓存按账号隔离。
- `app.py`：登录前停止加载业务数据；主任/医生不同导航和首页；医生工作量页面。
- SQL Agent、风险评分与报告生成共用同一权限上下文，避免只在页面上隐藏数据。
- 桌面浮窗和小组件使用相同账号与数据范围，每次提问检查会话。
- `scripts/manage_users.py`：服务端管理员建号、重置与停用工具。
- 修复了 SQLite 连接未关闭导致 Windows 测试清理失败的问题。

## 边界

主任看本科室，医生看本人，是此次确认的权限规则。没有新增院级管理员，也没有添加真实患者诊疗功能。

`data/auth.db` 含账号和会话数据，已排除版本控制，交付源码包也不包含此文件；解压后的副本需要重新创建账号。云端需预先建号并使用持久存储保存账号文件。当前实现针对小型模拟数据，真实院内生产环境需要结合统一身份服务和数据库权限进一步接入。

## 修改本地和云端账号

本机在项目根目录的 `账号密码配置.toml` 中维护账号。此文件被 Git 忽略，不上传。配置为唯一账号设置来源；改用户名或密码后，下一次登录或会话检查即生效，旧会话撤销。保留 `[accounts.director]`、`[accounts.doctor]` 两个区段名称，只改引号内的值，密码至少 6 位。已有账号保持原科室和医生绑定；已有账号时首次配置需使用其当前用户名。配置失效时暂停访问，不展示密码。不要与管理脚本交替重置同一账号，否则配置文件会在下一次读取时重新应用。

云端在 Streamlit → Manage app → Settings → Secrets 中保存相同的两个区段。当前版本首次配置主任和医生时，绑定模拟数据库的第一科室和第一医生；云端账号库重建时从 Secrets 恢复。重启可能丢失会话和本地账号变动；Secret 中的设置作为持久来源。现有账号停用状态不会被配置重新开启。

配置示例（下面是占位内容，必须换成自己的账号密码）：

```toml
[accounts.director]
username = "your_director_account"
password = "replace_with_private_password"

[accounts.doctor]
username = "your_doctor_account"
password = "replace_with_another_private_password"
```

本地文件不会自动同步到云端；更新云端账号请在 Secrets 中保存对应配置。两种来源同时出现时暂停运行，避免账号密码来回覆盖。
